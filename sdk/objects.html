Load objects

Load one object by primary key, page through object sets, iterate over every object, select properties, sort, and read the Osdk.Instance shape.

Foundry docsObject types

An object set from client(Employee) loads objects in three ways: one object by primary key, one page at a time, or every object with an async iterator. This page covers each method, its options, and the shape of the objects it returns.

The samples import a client from ./client. See Create a client to set one up.

Load one object

fetchOne takes a primary key and resolves to the object:

OptionTypeDefaultDescription
$selectPropertyKeys[]The API's default property setProperties to load. The primary key is always returned.
$includeRidbooleanfalseAdds $rid to the returned object.

fetchOne rejects when no object has that primary key, or when you cannot see it. The error is a PalantirApiError with the message Expected a single result but got 0 instead and no statusCode or errorName.

fetchOne exists only on object types. Interface object sets do not have it; see Interfaces.

Load a page

fetchPage resolves to one page of objects:

OptionTypeDefaultDescription
$selectPropertyKeys[]The API's default property setProperties to load. See Select properties.
$orderBy{ [property]: "asc" | "desc" } | "relevance"UnorderedSort order. See Sort.
$pageSizenumberServer defaultObjects in this page. It does not limit the total; continue with nextPageToken.
$nextPageTokenstringThe nextPageToken from the previous page.
$snapshotbooleanfalsePages through one consistent view of the data. See Paging and consistency.
$includeRidbooleanfalseAdds $rid to each object.
$includeAllBaseObjectPropertiesbooleanfalseInterface object sets only. Loads every property of the underlying object type. See Interfaces.

The page has three fields:

FieldTypeDescription
dataOsdk.Instance[]The objects in this page.
nextPageTokenstring | undefinedPass as $nextPageToken to load the next page. undefined on the last page.
totalCountstringThe number of objects in the set, as a string.

fetchPageWithErrors takes the same options and resolves to a Result of the page instead of rejecting.

Load every object

asyncIter loads page after page until it has every object in the set, and yields them one at a time:

asyncIter accepts $select, $orderBy, $includeRid, and $includeAllBaseObjectProperties. It requests pages of 10,000 objects and always requests a snapshot.

Before you iterate over a large object type:

  • Pass $select with only the properties you read. Loading unused properties costs bandwidth and server time, and reading fewer properties afterwards does not undo it.
  • Handle each object as it arrives. Collecting every object into an array makes memory grow with the size of the set.
  • For counts, sums, and group-bys, use aggregate. It runs on the server and loads no objects.
  • For a sample or the first N objects, use fetchPage with $pageSize.

Paging and consistency

MethodLoadsSnapshot
fetchPage({ $pageSize })One page. Continue with nextPageToken.Only with $snapshot: true, passed on every page.
asyncIter()Every matching object, page after page.Always.
aggregate({ ... })Counts, sums, and groups only.Not applicable.

Without a snapshot, later pages can repeat or skip objects if objects are added, removed, or edited between requests. A snapshot configured for a function run still applies, whatever you pass.

With a snapshot, every page of a non-stream-backed object type reflects the same point in time, so a completed traversal returns each object exactly once. Paging fails if the snapshot expires or the server detects a paging inconsistency (PagingInconsistencyDetected). Stream-backed object types do not keep a snapshot across pages: changes during a traversal can make it fail, and exactly-once traversal is not guaranteed.

If an asyncIter traversal of a frequently updated object type fails:

  1. Aggregate instead, if you only need a summary.
  2. Select fewer properties and filter the set so the traversal finishes sooner.
  3. Loop over fetchPage without a snapshot and de-duplicate by $primaryKey. De-duplication removes repeated objects but cannot recover skipped ones.

Select properties

Without $select, the server returns its default property set for the object type. Vector properties, for example, are not in it. With $select, the result type narrows to the properties you asked for, so reading anything else is a type error:

Rules for $select:

  • The primary key is always returned, as a property and as $primaryKey.
  • Ontology-defined derived properties are not returned by default. Name them in $select.
  • Derived properties you add with withProperties are returned when $select is omitted. If you pass $select, name them in it too.

The object shape

Each object is an Osdk.Instance: its properties plus a few $ fields. Objects are frozen, so assigning to a property throws in strict mode.

FieldTypeDescription
$primaryKeyThe primary key typeThe object's primary key, such as 12345.
$apiNamestringThe API name of the type you queried: the object type, or the interface for interface queries.
$objectTypestringThe API name of the object's concrete object type. Differs from $apiName on interface objects.
$titlestring | undefinedThe value of the object type's title property.
$ridstringThe object's RID. Present only when you pass $includeRid: true.
$objectSpecifierstringA string that identifies the object across types.
$linkobjectAccessors for linked objects. See Links.
$as(type) => Osdk.InstanceViews the object as an interface it implements, or an interface object as its object type. See Interfaces.
$clone(changes?) => Osdk.InstanceReturns a copy, optionally with some property values replaced.

Nullable properties are typed T | undefined. Property values use these TypeScript types:
