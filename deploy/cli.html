CLI reference

Every @osdk/cli command and flag for deploying sites and widget sets, managing versions, syncing branched SDKs, and generating SDKs locally.

Foundry docsApplication hosting

@osdk/cli deploys your app to Foundry website hosting, manages its versions, publishes widget sets, keeps branched SDKs in sync, and generates SDKs from an Ontology. This page lists every command and flag.

Run the CLI

Run it with npx, or install it as a dev dependency to get the osdk binary:

CommandDescription
osdk site deployUpload a new version of your site and, by default, make it live.
osdk site versionList, get, set, unset, and delete site versions.
osdk widgetset deployPublish a new widget set version.
osdk widgetset versionList, inspect, and delete widget set versions.
osdk branch syncInstall the SDK versions published for your current branch.
osdk unstable typescript generateGenerate SDK source files from an Ontology. Unstable.
osdk unstable auth loginTest an OAuth sign-in from the terminal. Unstable.

osdk experimental is an alias for osdk unstable. Commands under it can change or be removed in any release.

Global options

OptionTypeDescription
--verbose, -vcountDebug logging. Pass -vv for trace logging, which includes every HTTP request.
--helpbooleanPrint the commands and options available at that level, such as osdk site version --help.

Each option also accepts its kebab-case form: --foundryUrl and --foundry-url are the same option.

Configuration

Options come from three places. The first one set wins:

  1. The command-line flag.
  2. An environment variable named OSDK_ plus the option in upper snake case, such as OSDK_FOUNDRY_URL, OSDK_APPLICATION, or OSDK_DIRECTORY.
  3. foundry.config.json, for the options it covers.

The CLI looks for foundry.config.json in the current directory and then each parent, and uses the first one it finds. A file holds either a site block or a widgetSet block, not both. The full schema is in Host on Foundry.

Tokens

Every site and widgetset command needs a Foundry token. The CLI uses the first of:

  1. --token <token>
  2. --tokenFile <path>, a file whose contents are the token
  3. The FOUNDRY_TOKEN environment variable
  4. The FOUNDRY_SDK_AUTH_TOKEN environment variable, which is deprecated and logs a warning

--token and --tokenFile cannot be used together. The token must be a JWT. Without one, the command exits with No token found.

osdk site

Manages the website hosted for a Developer Console application. Run it with a subcommand: deploy or version.

These options apply to every site subcommand:

OptionTypeDefaultDescription
--applicationstringsite.applicationThe application RID, such as ri.third-party-applications.main.application.<id>. Required.
--foundryUrlstringfoundryUrlThe Foundry stack URL. Must start with https://. Required.
--tokenstringA Foundry token. Conflicts with --tokenFile.
--tokenFilestringA path to a file containing a Foundry token. Conflicts with --token.

osdk site deploy

Zips the contents of a directory, uploads it as a new site version, and makes that version live.

OptionTypeDefaultDescription
--directorystringsite.directoryThe directory to upload, usually your build output. Required. Everything in it is zipped, with the directory itself as the root.
--versionstringThe version to create. Must be valid SemVer. Conflicts with --autoVersion; when site.autoVersion is set in the config file, --version overrides it.
--autoVersion"git-describe" | "package-json"site.autoVersion.typeCompute the version instead of passing --version. See Automatic versions.
--gitTagPrefixstringsite.autoVersion.tagPrefixWith git-describe, match only tags that start with this prefix, and strip it from the version. Without it, every tag matches and a leading v is stripped. Only valid with git-describe.
--uploadOnlybooleansite.uploadOnly, else falseUpload the version without making it live. The CLI prints a preview link instead.
--snapshotbooleanfalseUpload a snapshot version with automatic retention. The CLI never makes a snapshot live. Cannot be combined with --uploadOnly.
--snapshotIdstringAn alias to attach to the snapshot version. Requires --snapshot.

You must pass --version or --autoVersion, or set site.autoVersion in foundry.config.json. When the deploy succeeds, the CLI prints the live URL, https://<subdomain>. With --uploadOnly, it prints https://<subdomain>/.system/preview?previewVersion=<version> instead.

osdk site version

Manages existing versions. Run it with a subcommand.

CommandDescription
osdk site version listLists every version that is valid SemVer, newest first, and marks the live one (deployed).
osdk site version getPrints the live version, or No live site version set.
osdk site version set <version>Makes <version> live. Use it to roll back or to publish a version uploaded with --uploadOnly.
osdk site version unsetClears the live version after a confirmation prompt. The site is unreachable until you set a version again.
osdk site version delete <version>Deletes a version after a confirmation prompt. You cannot delete the live version, and deletion cannot be undone.
OptionApplies toTypeDescription
--yes, -yunset, deletebooleanSkip the confirmation prompt.

Site errors

The CLI turns Foundry errors into these messages:

MessageCauseWhat to do
The site version already existsA version with that number was uploaded before.Use a new version. Versions are immutable.
The site version is invalid and must be a valid SemVer stringThe version is not SemVer.Fix --version, or the tag or package.json version that --autoVersion reads.
The site contains too many versionsThe application reached its version limit, shown in the message.Delete old versions with osdk site version delete.
The .zip file contains too many filesThe build output has more files than the limit.Reduce the number of files in the build.
The .zip file contains a file ... that is too largeOne file exceeds the size limit.Shrink or split that file.
The website version is being scanned for vulnerabilities and cannot be deployed yetFoundry is still scanning the upload.Deploy with --uploadOnly, then make the version live after the scan, with osdk site version set or from Website hosting in Developer Console.
The site version to delete is live and cannot be deletedYou tried to delete the live version.Set another version live first.
The site version could not be foundThe version does not exist.Check osdk site version list.

A 401 means the token is invalid or expired; a 403 means it lacks the permission or scopes for the request.

osdk widgetset

Publishes and manages widget sets for Workshop custom widgets. Run it with a subcommand: deploy or version. Publish a widget set covers the build and the manifest.

These options apply to every widgetset subcommand:

OptionTypeDefaultDescription
--widgetSetstringwidgetSet.ridThe widget set RID. Required.
--foundryUrlstringfoundryUrlThe Foundry stack URL. Must start with https://. Required.
--tokenstringA Foundry token. Conflicts with --tokenFile.
--tokenFilestringA path to a file containing a Foundry token. Conflicts with --token.

osdk widgetset deploy

Zips a directory and publishes it as a new widget set version. The version comes from the manifest at .palantir/widgets.config.json inside the directory; there is no version flag.

OptionTypeDefaultDescription
--directorystringwidgetSet.directoryThe directory to upload. Required.
--repositorystringwidgetSet.repositoryA code repository RID to publish through. The repository must be authorized to publish the widget set.
--branchNamestringThe current git branchThe git branch to publish from.

osdk widgetset version

CommandDescription
osdk widgetset version listLists published versions for the current git branch. Accepts --branchName.
osdk widgetset version info <version>Prints the details of one version.
osdk widgetset version delete <version>Deletes a version after a confirmation prompt. --yes or -y skips the prompt.

osdk branch sync

Installs the version of each generated SDK that matches your current branch: the newest prerelease published for that branch, or the stable latest release when you are on main. Develop on Foundry branches explains the workflow.

OptionTypeDefaultDescription
--branchNamestringThe current git branchThe branch to sync to. main, master, and a detached HEAD mean the default branch.
--packageNamestringSync only this SDK instead of every SDK found.
--dryRunbooleanfalsePrint what would be installed without changing anything.

osdk unstable branch sync is the same command under its earlier name.

osdk unstable typescript generate

Generates SDK source files from an Ontology, either by signing in to Foundry or from a saved Ontology metadata file. Generate an SDK shows when to use it.

OptionTypeDefaultDescription
--outDirstringWhere to write the generated files. Required.
--versionstringThe SDK version: dev or a SemVer string. Sent in the request user agent, and used as the package version with --asPackage. Required.
--foundryUrlstringLoad the Ontology from this stack. Requires --clientId. Alias: --stack.
--clientIdstringThe OAuth client ID to sign in with. Requires --foundryUrl.
--ontologyRidstringWith --foundryUrl, use this Ontology. Needed when the client can see more than one.
--branchstringWith --foundryUrl, the Foundry branch RID to load the Ontology from.
--ontologyWritePathstringWith --foundryUrl, also save the loaded Ontology metadata as JSON at this path.
--ontologyPathstringGenerate from an Ontology metadata JSON file instead of Foundry. Conflicts with --foundryUrl and --clientId.
--packageType"commonjs" | "module""commonjs"The module format of the project you generate into.
--cleanbooleanDelete --outDir before generating.
--skipPackageJsonUpdatebooleanfalseDo not add @osdk/api and @osdk/client to the nearest package.json.
--externalObjectsstringImport these object types from another generated SDK instead of generating them, as ApiName:@scope/package pairs separated by commas.
--externalInterfacesstringThe same, for interfaces.
--experimentalOntologyMetadatabooleanfalseAlso emit the raw Ontology metadata as an ./experimental/ontology-metadata export. May change or be removed.
--asPackagebooleanGenerate a standalone package with its own package.json. Requires --packageName and --beta.
--packageNamestringThe package name when using --asPackage.
--betabooleanRequired with --asPackage.
--internalbooleanfalseFor the osdk-ts repository only. Writes workspace: dependency versions.

Pass either --ontologyPath, or --foundryUrl and --clientId.

osdk unstable auth login

Runs the OAuth authorization code flow in your browser, to check that a client ID and redirect URL work. It does not save or print the token.

OptionTypeDescription
--foundryUrlstringThe Foundry stack URL. Required. Alias: --baseUrl.
--clientIdstringThe OAuth client ID. Required. Alias: --applicationId.

The CLI listens on port 8080 and uses http://localhost:8080/auth/callback as the redirect URL, so that URL must be allowed on OAuth & scopes in Developer Console and port 8080 must be free. It requests the offline_access, api:read-data, and api:use-ontologies-read scopes. osdk unstable typescript generate --foundryUrl uses the same sign-in.

Host on Foundry

Build your OSDK app with Vite and deploy it to Foundry website hosting with osdk site deploy, foundry.config.json, versions, previews, and rollbacks.

Develop on Foundry branches

Point your OSDK app at a Foundry global branch with osdk branch sync, @osdk/vite-plugin-branch, and the beta UNSTABLE_DO_NOT_USE_BRANCH client option.
