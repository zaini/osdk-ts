Users and groups

Look up users, search and list them, read group memberships, manage group members, and read markings with @osdk/foundry.admin.

Foundry docsUser APIGroup API

@osdk/foundry.admin reads and manages Foundry users, groups, and markings. Use it to show who is signed in, resolve user IDs to names, check group membership, and list the markings a user can view.

Every sample takes a client from createClient or createPlatformClient; see Set up. Reads need the api:admin-read scope and writes need api:admin-write. In React, the hooks in @osdk/react/platform-apis wrap several of these calls; see Users and markings in React.

Get the signed-in user

Users.getCurrent returns the user the token belongs to:

A User has these fields:

FieldTypeDescription
idstringThe user ID. Other endpoints take this as userId or principalId.
usernamestringThe username.
givenNamestring | undefinedFirst name.
familyNamestring | undefinedLast name.
emailstring | undefinedEmail address.
realmstringThe authentication realm the user belongs to.
organizationstring | undefinedRID of the user's primary organization.
status"ACTIVE" | "DELETED"Whether the user is active.
attributesRecord<string, string[]>Attributes from the identity provider.

Users.get takes a user ID. Pass status: "DELETED" to resolve a user who has been removed, for example the author of an old record:

Search and list users

Users.search runs a case-insensitive prefix search on username, given name, and family name. It only returns active users:

Users.list lists every user, one page at a time. Its query parameters:

OptionTypeDefaultDescription
include"ACTIVE" | "DELETED"Active usersWhich users to list. Pass "DELETED" to list removed users.
pageSizenumberPreferred page size. The server can return more or fewer.
pageTokenstringnextPageToken from the previous page.

To read every page, use the paginate helper from Call platform APIs.

Read group memberships

Groups.listCurrent returns every group the signed-in user belongs to, directly or through another group. It needs no scope, so any signed-in user can call it, but it is a preview endpoint:

For any other user, GroupMemberships.list returns the IDs of their groups. Set transitive: true to include groups they belong to through other groups, then resolve the IDs with Groups.getBatch:

This reads one page. Paginate with pageToken for users in many groups.

A Group has id, name, description, realm, organizations (organization RIDs), and attributes.

Find groups and their members

Groups.search runs a prefix search on group name. GroupMembers.list returns a group's members, which can be users or groups:

OptionTypeDescription
transitivebooleanInclude members of nested groups.
includeExpirationsbooleanInclude each member's expiration, when one is set.
pageSize, pageTokenPagination. See Paginate.

Each member is { principalType: "USER" | "GROUP", principalId, expiration? }.

Add and remove group members

Adding and removing members needs api:admin-write and permission to manage the group. Both take the group ID and a list of principal IDs, which can be user or group IDs, and resolve to undefined:

expiration is optional. Without it, the membership does not expire.

Read markings

Markings restrict who can view a resource. Users.getMarkings returns the IDs of the markings a user is a member of, and Markings.list and MarkingCategories.list return the markings and categories the token can see. Join them on categoryId:

Markings.list and MarkingCategories.list accept at most 100 per page and include deleted entries unless you pass includeDeleted: false. Paginate to read them all. To look up specific markings, use Markings.get or Markings.getBatch.

Marking fieldDescription
idThe marking ID.
categoryIdThe category it belongs to.
name, descriptionDisplay text.
organizationThe organization RID, for organization markings.
deletedWhether the marking has been deleted.
createdTime, createdByWhen and by whom it was created.

Listing who can view a marking, with MarkingMembers.list, needs api:admin-write because only marking administrators can see its members.

For classification-based access control (CBAC), CbacBanners.get returns the banner text and colors for a set of marking IDs. It is a preview endpoint; see the example in Call platform APIs.
