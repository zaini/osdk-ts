Links and actions

Relate object types with defineLink and define action types with the create, modify, and delete helpers from @osdk/maker.

Foundry docsLink typesAction types

Link types connect object types, so that an Employee can reach its Office. Action types describe the edits users can make, such as changing an employee's job title. Define both with @osdk/maker in your .ontology/ontology.mts file.

Link types

defineLink supports three kinds of link, chosen by the keys you pass:

KindKeysJoined on
One-to-manyone, toMany, manyForeignKeyPropertyA foreign key property on the "many" object type.
Many-to-manymany, toManyA link dataset of primary key pairs.
Intermediarymany, toMany, intermediaryObjectTypeAn object type that sits between the two, joined by two one-to-many links.

defineLink records the link without looking up its object types, so a link can refer to an object type that is defined later in the file. Maker checks the link when it compiles the ontology.

One-to-many

Each side's metadata.apiName is the name of the link as seen from that side's object type. The one side's name leads to many objects, and the toMany side's name leads to one:

These two links give the generated SDK the following link names:

Object typeLinkLeads to
OfficeoccupantsMany Employee objects whose officeId is the office's primary key.
EmployeeofficeThe one Office named by officeId.
EmployeereportsMany Employee objects whose leadId is this employee's primary key.
EmployeeleadThe one Employee named by leadId.

manyForeignKeyProperty must be a property of the toMany object type, with the same type as the one object type's primary key. Set cardinality: "OneToOne" when each object on the one side links to at most one object on the toMany side; the default is "OneToMany".

Many-to-many

Maker backs a many-to-many link with a dataset named link-<apiName> that has one column per primary key. When both object types use the same primary key name, the columns get _from and _to suffixes.

Status

A link's status is "active", "experimental", "example", or { type: "deprecated", message, deadline, replacedBy? }. It must agree with the object types it connects: if either side is deprecated, the link must be deprecated, and if either side is experimental or example, the link must be experimental or example.

Action types

Most actions create, change, or delete one object. The helpers below generate an action type from an object type: one parameter per property, the logic rule, and a default parameter order.

HelperDefault API nameParametersRule
defineCreateObjectActioncreate-object-<object>Every property, including the primary keyAdds an object.
defineModifyObjectActionmodify-object-<object>objectToModifyParameter, then every property except the primary keyModifies the chosen object. Each parameter defaults to the object's current value.
defineCreateOrModifyObjectActioncreate-or-modify-<object>objectToCreateOrModifyParameter, then every property except the primary keyModifies the chosen object, or creates one. Each parameter defaults to the object's current value.
defineDeleteObjectActiondelete-object-<object>objectToDeleteParameterDeletes the chosen object.

<object> is the object type's API name in lowercase with hyphens, so Employee gives modify-object-employee. Parameters skip vector properties, properties in excludedProperties, and properties set by nonParameterMappings; create and create-or-modify also skip derived properties. For interfaces, see Interface actions.

Action API names must contain lowercase letters and digits in segments separated by - or .. The SDK generator converts them to camelCase, so modify-employee is modifyEmployee in your generated SDK.

The parameter IDs of the chosen object are exported as constants:

Configure parameters

parameterConfiguration is keyed by parameter ID, which for property parameters is the property's API name. A key that is not a property adds a new parameter, and needs customParameterType.

OptionTypeDescription
displayNamestringThe parameter's label. Defaults to the property's display name.
descriptionstringHelp text under the parameter.
requiredboolean | { listLength: { min?: number; max?: number } }Whether a value is required. Defaults to true when the property sets nullability.noNulls, and for arrays to a minimum length of 1 when it sets noEmptyCollections.
allowedValuesAllowedValuesThe values the parameter accepts, such as { type: "oneOf", oneOf }, { type: "range", min?, max? }, or { type: "text", minLength?, maxLength?, regex? }. Defaults to what the property type allows.
defaultValueOntologyIrParameterPrefillA prefilled value.

customParameterTypeActionParameterTypeThe type of a parameter that is not a property, such as "string" or "booleanList".

A conditional override is one of:

OverrideEffect when condition passes
{ type: "visibility", condition, then? }Sets visibility to then: "editable", "disabled", or "hidden".
{ type: "disabled", condition, then? }Disables the parameter.
{ type: "required", condition }Makes the parameter required.
{ type: "defaultValue", condition, defaultValue }Uses a different default.
{ type: "constraint", condition, constraint }Uses different allowed values.

Conditions

Validation rules and overrides take a ConditionDefinition:

ConditionPasses when
{ type: "group", name }The user is in the group chosen for the input name when the ontology is installed.
{ type: "parameter", parameterId, matches }The parameter's value equals matches, such as { type: "staticValue", staticValue: { type: "string", string: "Engineering" } }.
{ type: "and" | "or", conditions }All or any of conditions pass.

Who can submit

actionLevelValidation is a list of rules that must all pass before a user can submit. displayMetadata.failureMessage is shown when a rule fails.

Set properties without a parameter

nonParameterMappings sets a property from something other than user input. The property gets no parameter.

ValueSets the property to
{ type: "currentUser" }The ID of the user who submits the action.
{ type: "currentTime" }The time the action is submitted.
{ type: "uuid", linkId? }A new UUID. Properties that share a linkId get the same UUID.
{ type: "staticValue", staticValue }A fixed value.
{ type: "parameterId", parameterId }The value of another parameter, such as a custom parameter.

Form sections

Each entry in sections has an id, a displayName, and the parameters it holds, plus optional description, defaultVisibility ("visible" or "hidden"), columnCount (1 or 2), showTitleBar, collapsedByDefault, style ("box" or "minimal"), and conditionalOverrides.

Define an action from rules

defineAction takes the parameters and logic rules directly, for actions the helpers do not cover. The rules use the Ontology IR rule types, such as addObjectRule, modifyObjectRule, deleteObjectRule, addOrModifyObjectRuleV2, and addInterfaceRule.

defineAction throws when there are no rules, when parameter IDs repeat, or when a rule or section references a parameter that is not defined.
