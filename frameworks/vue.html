Vue

Build a Vue app on OSDK with the create-app Vue template, set up sign-in, and query objects and apply actions from components with @osdk/client.

Use @osdk/client directly from Vue components: there is no Vue-specific OSDK package. The vue template of @osdk/create-app gives you a Vite app with sign-in, routing, and a configured client.

Create a Vue app

Run @osdk/create-app with the vue template:

The CLI asks for your Foundry URL, application RID, OAuth client ID, and SDK package, the same prompts as the React template. Quickstart lists every prompt and its flag. The template uses SDK version 2.x unless you pass --sdkVersion 1.x.

Then install and start the dev server:

Open http://localhost:8080. FOUNDRY_TOKEN must be able to read your SDK's npm registry; see Installation.

src/client.ts exports one auth and one client for the whole app. It reads its configuration from the <meta> tags in index.html, so you can change values per environment without touching code:

The generated file also throws when a tag still holds an unreplaced %VITE_...% value, which means the variable is missing from your .env file.

The first request starts sign-in. Foundry redirects back to /auth/callback, where AuthCallback.vue exchanges the code and returns to /:

Reactivity tips

  • Store results in shallowRef. OSDK objects are frozen. Vue does not wrap frozen objects in reactive proxies, so changes are never detected inside them anyway. Replace the whole value when new data arrives.
  • Never mutate an object to update the UI. Assigning to employee.jobTitle throws in strict mode. Apply an action, then fetch again.
  • Key lists by $primaryKey. It is unique within an object type and stable across fetches.
  • Create the client once. Import client from src/client.ts in every component. Do not call createClient inside setup.
  • Do not reach for @osdk/react. Its hooks need React. For a shared cache in Vue, use the observable client below.

Keep lists live with the observable client

createObservableClient from @osdk/client/observable is the cache that powers @osdk/react. It deduplicates requests, shares objects between subscribers, and refetches affected lists after an action you apply through it. Wrap it in a composable:

watchEffect resubscribes when department() changes and unsubscribes when the component unmounts. Call useEmployees(() => props.department) from <script setup>.

Apply actions through observableClient.applyAction(modifyEmployee, { ... }) instead of client(modifyEmployee).applyAction(...). When it resolves, every subscribed list and object of the edited types refetches, so the component updates without a manual reload. It throws like applyAction, so await it in try/catch.

Deploy

npm run build writes the app to dist/, which foundry.config.json already points at. Before you build for production, set VITE_FOUNDRY_REDIRECT_URL in .env.production to your hosted app's /auth/callback and add that URL on OAuth & scopes. Hosting covers uploading the build to Foundry.

Loading and errors

Render @osdk/react hooks correctly while data loads, refreshes, or fails, and narrow errors to PalantirApiError and ActionValidationError.
