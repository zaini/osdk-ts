Expo and React Native

Build an iOS, Android, and web app on OSDK with the create-app Expo template, sign in with expo-auth-session, and query objects from React Native screens.

The expo template of @osdk/create-app gives you an Expo Router app that signs in to Foundry and calls @osdk/client on iOS, Android, and the web. Sign-in works differently from the browser templates, so read Sign in before you configure redirect URLs.

Create an Expo app

Run @osdk/create-app with the expo template:

The CLI asks for your Foundry URL, application RID, OAuth client ID, and SDK package. Quickstart lists every prompt and its flag. The Expo template supports SDK version 2.x only.

Answer No to the CORS proxy prompt, or pass --corsProxy false. The Expo template has no proxy server, but a Yes still sets EXPO_PUBLIC_FOUNDRY_API_URL to http://localhost:8080 in .env.development, so every request goes to the Expo dev server instead of Foundry.

Then install and start the app:

FOUNDRY_TOKEN must be able to read your SDK's npm registry; see Installation.

Sign in

The browser templates use createPublicOauthClient from @osdk/oauth, which signs in by navigating the page to Foundry and back. A native app cannot do that, so the Expo template runs the same authorization code flow with PKCE through expo-auth-session instead, which opens Foundry's sign-in page in a system browser session and returns the code to the app.

Store the token

foundry/Auth.ts keeps the token response in a module variable. getValidAuthToken is the token provider you pass to createClient; it throws until the user has signed in:

The token lives only in memory. The template neither refreshes nor persists it, so the user signs in again when the app restarts or the access token expires.

Run the authorization flow

The Login tab points useAuthRequest at Foundry's authorize and token endpoints under /multipass/api/oauth2, then exchanges the returned code for a token. This version adds error handling to the generated screen:

Request only the scopes your app needs, and allow each of them for your application on OAuth & scopes in Developer Console.

On web, promptAsync opens Foundry in a popup. Foundry redirects the popup to your app's root URL, where app/(tabs)/index.tsx calls WebBrowser.maybeCompleteAuthSession() from expo-web-browser. That call hands the result back to the original window and closes the popup. Keep it in whichever screen renders at the redirect path.

Register redirect URLs

makeRedirectUri({ path: "" }) returns a different URL on each platform, and each one must be registered exactly on OAuth & scopes:

Where the app runsRedirect URL
Web, local developmenthttp://localhost:8080, with no /auth/callback path
Web, hosted on FoundryYour site's root URL, such as https://<subdomain>.<your-domain>.palantirfoundry.com
iOS and AndroidA URL with the scheme from app.json. The template's scheme is my-app; change it to one unique to your app.

To see the exact value on a device, render or log redirectUri from the Login screen and copy it into Developer Console.

Use @osdk/react hooks

@osdk/react does not touch the DOM, so its hooks work in React Native screens. The template lists @osdk/react in package.json but does not use it, and pins it to ^0.7.0, a release line from before @osdk/react shared a version number with @osdk/client. Metro configuration

metro.config.js makes three changes to Expo's default Metro config:

  • Enables package exports (resolver.unstable_enablePackageExports: true), because the OSDK packages publish their entry points, such as @osdk/client/observable, through the exports field.
  • Resolves @osdk packages with the browser, require, and import conditions, so Metro picks their browser builds on every platform.
  • Loads .env.development with dotenv and adds react-native-svg-transformer for .svg imports.

Keep the first two if you replace the file. The template adds no polyfills.

Deploy the web build

npm run build exports the web build to dist/, which foundry.config.json points at. Register your site's root URL as a redirect URL first, then follow Hosting. Publishing to the App Store or Google Play uses Expo's own build tooling and is not covered by the template.
