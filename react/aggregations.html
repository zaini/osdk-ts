Aggregate objects

Count, sum, average, and group objects on the server with useOsdkAggregation, without loading the objects into the browser.

useOsdkAggregation asks the server for counts, sums, averages, and other metrics over a set of objects, optionally grouped by property values. Only the results come back, so a total over a million objects costs one small response.

Count and summarize

Pass an object type and an aggregate with a $select. Each key in $select is a metric to compute:

$count is read as data.$count. A "property:metric" key is read as data.property.metric, so "salary:avg" becomes data.salary.avg. The result is fully typed from the keys you pass.

Metrics

KeyProperty typesResult
$countnumber
"property:sum", "property:avg"Numericnumber, or undefined when no object has a value
"property:min", "property:max"Numeric, date, timestampSame type as the property, or undefined
"property:exactDistinct"Allnumber of distinct values
"property:approximateDistinct"AllEstimated number of distinct values. Faster on large object types.

TypeScript rejects a metric that does not fit the property, such as avg on a string.

Filter before aggregating

where takes the same clause as useOsdkObjects. intersectWith adds clauses that every object must also match.

withProperties defines derived properties that where can filter on.

Group results

Add $groupBy to get one row per group. data is then an array; each row has a $group object with the group's values, plus the metrics from $select.

The value of each $select key sets the order of the rows: "asc" or "desc" sorts by that metric, and "unordered" leaves it to the server. Above, departments come back largest first.

Grouping strategies

StrategyProperty typesGroups by
"exact"AllEach distinct value.
{ $exactWithLimit: n }AllEach distinct value, at most n groups.
{ $exact: { $limit?, $includeNullValue: true } }AllEach distinct value, plus a group for missing values. $group values are then nullable.
{ $exact: { $limit?, $defaultValue: "…" } }AllEach distinct value, with missing values grouped under the default.
{ $fixedWidth: n }NumericBuckets of width n.
{ $ranges: [[start, end], …] }Numeric, date, timestampThe ranges you list. $group holds { startValue, endValue }.
{ $duration: [n, unit] }Date, timestampTime buckets, such as [1, "years"] or [1, "month"]. Dates accept day units and up; timestamps also accept seconds, minutes, and hours.

Typing $ranges and $duration

The hook infers aggregate as a constant, which makes the tuples in $ranges and $duration read-only. TypeScript then loses the result type and row.$group has no properties. Assert the tuple type to keep it: { $ranges: [[0, 50000], [50000, 100000]] as [number, number][] } or { $duration: [1, "years"] as [1, "years"] }.

Aggregate an object set

To aggregate a set that a type and a where cannot express, such as a pivot or a union, pass it as objectSet. The first argument must be the type of that set. where, intersectWith, and withProperties still apply on top of it.

objectSet must be an ObjectSet, not undefined, and works with object types only. The objectSet field returned by useOsdkObjects and useObjectSet is undefined until their first page loads, so build the set with the client as above when you need it on the first render. See Work with object sets for union, intersect, and subtract.

Refresh and disable

Aggregations recompute when an action changes the object type, like other queries. refetch invalidates the object type, which refetches every cached query for that type.

With enabled: false, the hook does not fetch and returns data: undefined, isLoading: false, and error: undefined. refetch does nothing while disabled.
