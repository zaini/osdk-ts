Users and markings

Load Foundry users, markings, and CBAC classification banners in React with the hooks in @osdk/react/platform-apis.

Foundry docsFoundry REST APIs

The hooks in @osdk/react/platform-apis call Foundry platform APIs for users and markings with the client from OsdkProvider. Use them to show who is signed in, look up other users, list markings, and render classification banners.

Install the platform packages

The hooks depend on two optional peer packages. Install them before importing from @osdk/react/platform-apis:

Without them, the bundler fails with Rollup failed to resolve import "@osdk/foundry.admin" or a similar error. The rest of @osdk/react works without these packages.

Every hook needs an OsdkProvider above it. The signed-in user's token must allow the platform API you call; a missing permission comes back as an error.

Show the signed-in user

useCurrentFoundryUser loads the user the client's token belongs to:

OptionTypeDefaultDescription
enabledbooleantrueWhen false, no request is made.
FieldTypeDescription
currentUserUser | undefinedThe user, with id, username, givenName, familyName, email, realm, organization, status, and attributes.
isLoadingbooleantrue while the request runs.
errorError | undefinedSet when the request failed.
refetch() => voidRequests the user again.

Look up a user

useFoundryUser takes the user ID as its first argument and options second:

OptionTypeDefaultDescription
enabledbooleantrueWhen false, no request is made.
status"ACTIVE" | "DELETED""ACTIVE"Status of the user to look up. Pass "DELETED" to resolve users who have been removed.

The result has user, isLoading, error, and refetch. A new userId triggers a new request.

List users

useFoundryUsersList returns one page of users. Pass the previous page's nextPageToken as pageToken to load the next one:

OptionTypeDefaultDescription
enabledbooleantrueWhen false, no request is made.
include"ACTIVE" | "DELETED""ACTIVE"Which users to list.
pageSizenumber1000Preferred page size. The server can return more or fewer.
pageTokenstringundefinedToken for the page to load. Omit for the first page.
FieldTypeDescription
usersUser[] | undefinedThe users on this page.
nextPageTokenstring | undefinedToken for the next page. undefined on the last page.
isLoading, error, refetchAs for useCurrentFoundryUser.

Each page replaces the previous one. To show every page loaded so far, keep the users you have received in state.

List markings

useMarkings lists the markings the user can see, and useMarkingCategories lists the categories they belong to. Join them on marking.categoryId:

HookOptionDefaultReturns
useMarkingsincludeDeletedtruemarkings: Marking[], each with id, categoryId, name, description, and deleted.
useMarkingCategoriesincludeDeletedtruecategories: MarkingCategory[], each with id, name, description, markings (marking IDs), and deleted.
BothmarkingTypeAll typesOnly markings or categories of this type, such as "CBAC".

Both accept enabled and return isLoading, error, and refetch. Deleted entries are included unless you pass includeDeleted: false.

Get a user's markings

useUserViewMarkings returns the IDs of the markings a user can view. Without userId, it uses the signed-in user:

OptionTypeDefaultDescription
userIdstringSigned-in userThe user to look up.
enabledbooleantrueWhen false, no request is made.

The result has markingIds (string[] | undefined), isLoading, error, and refetch.

Show a classification banner

For classification-based access control (CBAC), useCbacBanner returns the banner text and colors for a set of marking IDs:

FieldTypeDescription
banner.classificationStringstringThe banner text.
banner.textColorstringText color.
banner.backgroundColorsstring[]One or more background colors.
banner.markingIdsstring[]The markings the banner represents.

useCbacMarkingRestrictions checks a proposed set of marking IDs before you apply it, for example in a marking picker:

FieldTypeDescription
restrictions.isValidbooleanWhether the markings form a valid classification: none are disallowed and every required constraint is met.
restrictions.userSatisfiesMarkingsbooleanWhether the signed-in user satisfies the markings.
restrictions.impliedMarkingsstring[]Markings that the selection implies.
restrictions.disallowedMarkingsstring[]Markings that are disallowed with the selection.
restrictions.requiredMarkingsstring[][]Required marking constraints, as groups of marking IDs.

Both hooks take { markingIds, enabled? }, return isLoading, error, and refetch, and make no request while markingIds is empty. They call preview CBAC endpoints, which must be available on your Foundry stack. For a ready-made picker, see the CbacPicker component.

How these hooks load data

These hooks do not use the object cache that powers useOsdkObjects and the other ontology hooks:

  • Each mounted hook makes its own request. Two components that call useCurrentFoundryUser make two requests. Call the hook once and pass the result down when that matters.
  • A hook requests again when an option changes. refetch requests again on demand.
  • While a request runs, the previous result is cleared and the data field is undefined.
  • When a request fails, isLoading stays true next to error. Check error before isLoading, as the examples on this page do.

Handle errors

All hooks return failures as an Error. When the failure comes from a Foundry API, it is a PalantirApiError, exported from @osdk/client. Narrow with instanceof to read its fields, all of which are optional:

FieldTypeDescription
errorNamestringStable identifier, such as UserNotFound. Switch on this.
errorCodestringError category, such as NOT_FOUND or PERMISSION_DENIED.
errorDescriptionstringHuman-readable description.
statusCodenumberHTTP status.
errorInstanceIdstringServer-side ID for this occurrence. Include it in bug reports.
parametersobjectExtra context from the server, such as { userId }.
