React widgets

Render a widget with FoundryWidget, read typed parameters and loading states with useFoundryWidgetContext, and emit events back to the host.

Foundry docsDevelop a widget setUse OSDK in a widget set

@osdk/widget.client-react connects a React tree to the Foundry host. FoundryWidget handles the message protocol, and useFoundryWidgetContext gives every component typed parameter values and an emitEvent function derived from your widget config.

Install

Projects from @osdk/create-widget already include these packages. To add them to an existing Vite and React project:

@osdk/widget.client-react supports React 18 and 19 and lists @osdk/client as a peer dependency. Add @osdk/client, @osdk/react, and your SDK package to call the Ontology.

Render FoundryWidget

Wrap the widget's root in FoundryWidget and pass its config. Importing the config in the entrypoint is also what lets the Vite plugin find it.

PropTypeDefaultDescription
configThe return type of defineConfigRequiredThe widget config. Every parameter and event type in the context comes from it.
childrenReact.ReactNodeRequiredThe widget.
clientClient from @osdk/clientAn OSDK client, used to hydrate object set parameters and to serialize object sets you emit. Required by the types when the config has an objectSet parameter.
initialValuesAsync value per parameter IDEvery parameter not-startedStarting values for asyncParameterValues before the host's first update.

On mount, FoundryWidget:

  1. Subscribes to host messages and sends widget.ready, so the host sends the first parameter values.
  2. Observes the size of document.body and sends widget.resize with its border-box width and height on every change.
  3. Sends widget.reload before a Vite full-page reload in development.
  4. Wraps children in an error boundary. An uncaught render error shows its stack trace, plus troubleshooting tips when NODE_ENV is not production. Add your own error boundary inside FoundryWidget to show a custom message instead.

Render one FoundryWidget per widget, at the root. It creates the widget client once, when it mounts.

Read parameters

useFoundryWidgetContext returns the context for the nearest FoundryWidget. The context is not generic at runtime, so bind your config's type once with withTypes and import that hook everywhere:

useFoundryWidgetContext<typeof MainConfig>() is equivalent. Outside a FoundryWidget, the hook returns a default context; see Render outside Foundry.

Loading states

parameters.state summarizes the parameters in the host's most recent update, in this order of precedence:

StateWhen
"failed"Any parameter failed. parameters.values keeps the values that did arrive.
"loading"Any parameter is loading for the first time.
"reloading"Any parameter is reloading. Values keep their previous contents.
"not-started"Any parameter has not started loading.
"loaded"Every parameter loaded.

While the state is not-started or loading, parameters.values is {}, so give every read a fallback and keep rendering. Show progress next to the content instead of replacing it:

Emit events

emitEvent(eventId, { parameterUpdates }) sends a widget.emit-event message. TypeScript limits eventId to the config's events and requires a value for every ID in the event's parameterUpdateIds. The call returns nothing and does not report whether the host acted on the event.

In the example above, handleAdd emits updateTodoItems with the new list. The widget does not keep its own copy: when the host writes the update to the variable bound to todoItems, the new list arrives through parameters.values and the widget re-renders. The template's counter works the same way, reading counterValue and emitting setCounterValue with the next number.

Object set parameters

For an objectSet parameter, the host sends an object set RID. Pass an OSDK client to FoundryWidget, and the value in parameters.values gains an objectSet you can query, typed by the parameter's allowedType.

Query the set with useObjectSet from @osdk/react. Hydrated object sets are cached per parameter, so the objectSet reference only changes when the host sends a new RID, and it is safe to pass straight to hooks. To emit an object set, pass an ObjectSet from @osdk/client:

emitEvent turns each ObjectSet into a temporary object set RID with an extra request before it sends the event. Because of that step:

  • If you emit the same event again before the request finishes, only the last call is sent.
  • Errors, such as a failed request, are not reported to the caller.
  • Emitting an object set without a client on FoundryWidget fails, and so does receiving one.

See Work with object sets for filtering, pivoting, and combining the sets you receive.

Render outside Foundry

FoundryWidget needs the host API that Foundry injects. Outside Foundry and developer mode, it throws Invariant failed: [FoundryWidgetClient] Missing __PALANTIR_WIDGET_API__ in window when it renders.

Components below it still render on their own: without a FoundryWidget ancestor, useFoundryWidgetContext returns a default context whose parameters.state is not-started, whose parameters.values is {}, and whose emitEvent does nothing. Because widget components already handle empty values, you can render them directly in unit tests and Storybook.

To start asyncParameterValues in a known state before the host's first update, pass initialValues to FoundryWidget. It does not affect parameters.values or parameters.state, which stay {} and not-started until the first host.update-parameters message.
