The Ontology and your SDK

How object types, links, actions, functions, interfaces, and object sets map to the generated SDK and to Osdk.Instance values in TypeScript.

Foundry docsOntologyObject types

Your generated SDK is a typed description of part of a Foundry Ontology. This page explains what each Ontology concept becomes in TypeScript, so you can read the SDK and the values it returns.

Ontology concepts

ConceptWhat it isIn the generated SDKHow you use it
Object typeA schema for real-world entities, such as employees.A definition, Employee, plus the namespace types Employee.Props and Employee.OsdkInstance.client(Employee) returns an object set of every Employee.
PropertyA typed field on an object type.A key in Employee.Props, typed from the property's base type.Read it on an instance: employee.fullName.
Primary keyThe property that uniquely identifies an object.primaryKeyApiName and primaryKeyType on the definition.client(Employee).fetchOne(12345), or employee.$primaryKey.
Link typeA relationship between two object types.Entries in Employee.Links.employee.$link.lead for a single link, employee.$link.reports for many.
Action typeA transaction that edits objects.A definition, modifyEmployee.client(modifyEmployee).applyAction({ ... }).
Function (query)Server-side logic that reads the Ontology and returns a value.A definition, such as getEmployeeMetrics.client(getEmployeeMetrics).executeFunction({ ... }).
InterfaceA shared shape that several object types implement.A definition with its own properties.client(MyInterface).fetchPage(), then instance.$as(Employee).
Object setA lazy, composable query over objects.Employee.ObjectSet.client(Employee).where({ ... }).pivotTo("lead").

The generated package does not contain a client. It exports definitions, which are plain metadata. You pass a definition to a client created with createClient from @osdk/client, and the client does the work:

See Create a client to set up client.

Why client(Employee)

The SDK separates the code that knows your Ontology (the generated package) from the code that talks to Foundry (@osdk/client). That design has practical effects:

  • Smaller bundles. Each definition is a small named export. Bundlers drop the ones you do not import, so the SDK's cost scales with what you use, not with the size of the Ontology.
  • One runtime. Several generated SDKs share the same @osdk/client code instead of each shipping its own.
  • Fixes without regenerating. A bug fix in @osdk/client reaches you through a dependency update. You do not need to regenerate the SDK.

If you want autocomplete across the whole Ontology, import the namespace exports. Tree-shaking still removes what you do not reference:

The generated package also exports $Actions, $Queries, and $Interfaces, and $ontologyRid when the SDK was generated for a single Foundry environment.

Instances are immutable

Instances are frozen, and their properties are readonly. To get a changed copy, call $clone:

$clone throws if the update changes the primary key. It does not write anything to Foundry. Use it to build optimistic state for an action, as shown in Optimistic updates. To change data, apply an action.

Dates and timestamps

The SDK returns dates and timestamps as ISO 8601 strings instead of Date objects or a date library's types. This keeps a large date library out of your bundle, lets you use the date library you already have, and avoids parsing values you never read.

Object sets

An object set describes which objects you want. Building one does not send a request; only fetching does:

MethodReturnsDescription
where(clause)Object setFilters the set.
union(...sets), intersect(...sets), subtract(...sets)Object setCombines sets of the same type.
pivotTo(link)Object setFollows a link to the linked type.
withProperties(...)Object setAdds derived properties computed on the server.
fetchPage(options)Promise of a pageFetches one page: data, nextPageToken, and totalCount.
fetchOne(primaryKey)Promise of an instanceFetches one object. Object types only.

subscribe(listener)SubscriptionReceives changes to the set over a WebSocket.

In React, pass the same filters to useOsdkObjects or build a set with useObjectSet.
